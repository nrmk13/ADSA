# Button

The one control that submits, saves, confirms or cancels. Anything that navigates is
a link, not a button — an agent that reaches for `Button` to change the page is the
most common mistake made against this system.

## Import

```tsx
import { Button } from "@acme/ui/button";
```

## Usage

```tsx
<Button color="primary" size="md">Save changes</Button>
```

One `color="primary"` per screen. Everything else on the screen is `secondary`, and
`destructive` is for the action a person cannot undo.

```tsx
<Button color="destructive" isLoading>Deleting…</Button>
```

`isLoading` keeps the button in the layout and sets `aria-busy`; it does not disable
it, so say what is happening in the label rather than leaving a spinner alone.

## Notes

- There is no `ButtonGroup` in this system, and no icon-only variant. Both are in
  [GAPS.md](../GAPS.md) with what to use instead.
- Every remaining prop is a native `<button>` prop, `type` included. A button inside
  a form submits it unless you say `type="button"`.

### Keyboard and accessibility

**Role:** button · **Accessible name:** The text inside it. An icon-only button has no name in this system, which is why there is not one.

| Key | What happens |
| :-- | :-- |
| `Enter / Space` | Activates it |
| `Tab` | Moves to it; a disabled button is skipped |

**Focus.** Native. Never remove the focus ring: it is a token, not a style.

`isLoading` sets `aria-busy` and leaves the button focusable, so a person is not thrown out of the page while it works.

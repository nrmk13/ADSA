# Pattern: empty state

**When to use it.** Any surface with nothing in it yet. It is a pattern rather than a
component because the words carry all the work, and words cannot be a prop.

## Skeleton

```tsx
import { Card, CardBody } from "@acme/ui/card";
import { Button } from "@acme/ui/button";

<Card>
    <CardBody>
        <h2>No customers yet</h2>
        <p>Customers appear here once someone signs up, or you can add one now.</p>
        <Button color="primary">New customer</Button>
    </CardBody>
</Card>
```

Three parts, always in this order: what is missing, why the surface is empty, and the
one thing to do about it. An empty state without an action is a dead end.

## States

**Nothing yet.** The skeleton above. Say what will appear here, not that the list is
empty — people can see that.

**Nothing found.** A filter is responsible. Name the filter, offer to clear it, and
keep the filters on screen. This is a different state from "nothing yet" and writing
one for both is the most common version of this mistake.

**Error.** Not an empty state. A surface that failed is an error with a retry; showing
"no customers yet" when the request failed is a lie the page tells confidently.

**Permission denied.** Not an empty state either. Say the data exists and who can see
it.

## Traps

- Do not use a `Badge` here. Nothing has a status yet.
- The action is the primary one for the surface, and it is the same action as the
  button in the page header — the same label, so people do not think it does
  something else.
- No illustration-only empty states: an image with no heading is silent to a screen
  reader and to anyone in a hurry.

## What it is not

It is not an onboarding screen. This is one empty surface, not a tour of the product.

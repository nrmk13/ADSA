# Pattern: list page

**When to use it.** A page whose job is to find one record among many: customers,
invoices, projects. If people arrive knowing which record they want, this is still
the pattern — search is part of it.

## Skeleton

```tsx
import { Table, TableRow, TableCell } from "@acme/ui/table";
import { Input } from "@acme/ui/input";
import { Button } from "@acme/ui/button";
import { Badge } from "@acme/ui/badge";

<section>
    <header>
        <h1>Customers</h1>
        <Button color="primary">New customer</Button>
    </header>

    <Input label="Search customers" type="search" />

    <Table density="compact">
        <TableRow>
            <TableCell>Acme Ltd</TableCell>
            <TableCell><Badge tone="success">Active</Badge></TableCell>
            <TableCell><Button color="secondary" size="sm">Open</Button></TableCell>
        </TableRow>
    </Table>
</section>
```

The order is fixed: title and primary action, then filters, then the table, then
pagination. People scan pages in that order and so does a screen reader.

## States

**Loading.** Keep the header and the filters interactive and replace only the rows.
A page that greys out entirely loses the search term a person just typed.

**Empty — no records at all.** Use the [empty state](empty-state.md) pattern in place
of the table. Do not render an empty table with a header row: a table of nothing reads
as a broken table.

**Empty — no results for this filter.** Different from the above, and the difference
matters. Keep the table header, say which filter is responsible, and offer to clear
it. Never send someone to "create your first customer" when they have four hundred.

**Error.** Keep the filters. Say what failed and give a retry `Button`; a list that
fails is almost always retryable, and a full-page error throws away the state.

**Permission denied.** Show the page and the reason, not a redirect. Being told "you
cannot see invoices" is information; being bounced to the dashboard is a bug report.

## Traps

- Sorting state lives in the URL. Two people looking at "the overdue ones" must see
  the same page when one sends the other a link.
- Row click and row action fight each other. This system has no clickable row: put a
  `Button` in the last cell.
- A `Badge` column is a status, not a filter. The filter is the `Input` above.

## What it is not

It is not a dashboard: a dashboard answers "how are we doing", a list page answers
"where is that one". Do not put summary tiles above the table because the page looks
bare — the search field is what people came for.

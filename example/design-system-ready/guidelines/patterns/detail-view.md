# Pattern: detail view

**When to use it.** One record, everything known about it, and the actions available
on it. The page a list page links to.

## Skeleton

```tsx
import { Card, CardHeader, CardBody } from "@acme/ui/card";
import { Badge } from "@acme/ui/badge";
import { Button } from "@acme/ui/button";
import { Modal } from "@acme/ui/modal";

<article>
    <header>
        <h1>Acme Ltd</h1>
        <Badge tone="success">Active</Badge>
        <Button color="destructive">Delete</Button>
    </header>

    <Card>
        <CardHeader><h2>Billing</h2></CardHeader>
        <CardBody>Renews on the 4th.</CardBody>
    </Card>

    <Modal isOpen={isConfirming} onClose={cancel} title="Delete Acme Ltd">
        This removes every project in it. There is no undo.
    </Modal>
</article>
```

The record's name is the `<h1>`. Its state is a `Badge` beside it, never a coloured
background on the whole header.

## States

**Loading.** Show the heading as soon as the name is known — it usually arrives with
the navigation — and load the cards under it. The page title is the answer to "did I
open the right record".

**Empty.** A record with no activity yet still has a name and a state. Use an
[empty state](empty-state.md) inside the affected `Card`, not on the whole page.

**Error.** A record that failed to load is a page-level error with a retry. A card
that failed is a card-level error: the rest of the record is still true.

**Permission denied.** Show the record and hide the actions the person cannot take.
Do not disable them: a disabled button with no explanation is worse than no button.

## Traps

- The destructive action gets a `Modal` with the record's name in the title, so a
  person can see which record they are about to delete.
- Do not stack more than three `Card`s. Beyond that the page is a list of sections
  and needs its own navigation, which this system does not have — see
  [GAPS.md](../../GAPS.md).
- Status belongs in one place. A `Badge` in the header and a "status" row inside a
  card will disagree with each other eventually.

## What it is not

It is not a settings form: this shows a record and acts on it, a settings form edits
values in place. If the page is mostly `Input`s, it is the other pattern.

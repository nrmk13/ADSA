# Patterns

Components say what exists. Patterns say what to build. Match the task to a pattern
first, then open only that file — the bodies are long on purpose and are not meant to
sit in an agent's context all at once.

| When the task sounds like | Pattern | Components it uses |
| :-- | :-- | :-- |
| "a page listing all the X" | [List page](list-page.md) | `Table`, `Input`, `Button`, `Badge` |
| "let people change their X" | [Settings form](settings-form.md) | `Card`, `Input`, `Button` |
| "a page for one X" | [Detail view](detail-view.md) | `Card`, `Badge`, `Button`, `Modal` |
| "what if there is nothing yet" | [Empty state](empty-state.md) | `Card`, `Button` |

Every pattern below carries the same four sections: the skeleton, the four states
(loading, empty, error, denied), the traps, and what it is not. The states are the
half that gets skipped, and they are the half a person notices.

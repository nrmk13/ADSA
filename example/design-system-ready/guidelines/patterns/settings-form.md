# Pattern: settings form

**When to use it.** A page where someone changes values that already have a value.
Not a wizard, not a creation flow: everything here is already true, and the person is
editing it.

## Skeleton

```tsx
import { Card, CardHeader, CardBody } from "@acme/ui/card";
import { Input } from "@acme/ui/input";
import { Button } from "@acme/ui/button";

<form>
    <Card>
        <CardHeader><h2>Contact</h2></CardHeader>
        <CardBody>
            <Input label="Work email" hint="Used for billing receipts." />
            <Input label="Phone" />
        </CardBody>
    </Card>

    <Button color="primary" type="submit">Save changes</Button>
</form>
```

One `Card` per group of related settings, one save for the whole page. Per-field save
buttons look tidy and leave people unsure whether anything was kept.

## States

**Loading.** Render the cards and their headings with the fields disabled rather than
a blank page: the shape of the page is information too.

**Empty.** Does not occur — a settings form always has current values. If a section
can genuinely be empty, it is a list page.

**Error — the save failed.** Keep every value the person typed. Put the message above
the form, move focus to it, and leave the fields editable. Losing typed input on a
failed save is the single worst thing this pattern can do.

**Error — a field is invalid.** `isInvalid` on the field, the reason in its `hint`,
and a summary above the form linking to the first one. Do not disable the save button
to prevent submission: people then have no way to find out what is wrong.

**Permission denied.** Render the fields read-only with one line saying who can change
them. Hiding the section makes people think the setting does not exist.

## Traps

- No auto-save in this system. A form that saves as you type needs an undo, and there
  is no undo component — see [GAPS.md](../../GAPS.md).
- "Save" is a submit button, so `type="submit"`. A `Button` with no type inside a form
  submits it anyway, which is fine here and a bug in the cancel button beside it.
- Do not use a `Modal` to confirm a save. Confirm destructive things, not ordinary ones.

## What it is not

It is not a detail view. A detail view shows a record and offers actions on it; this
edits the values of something the person owns. When both are true, the settings form
is the page and the detail view is a section inside it.

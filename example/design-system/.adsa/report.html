The nine dimensions

Each one is scored 1, 3 or 5 from what is in the repository. The evidence under each row is what produced the number.

Agent instructions

5 / 5

When an agent opens this repo, does anything tell it how to use the system?

  • AGENTS.md, 20 lines.
  • Contains an import rule, a lookup command, token rules, a list of what is forbidden, a check to run before finishing.

At 5. Short and imperative: how to look a component up, how to import, which token classes are required, what is forbidden, what to run before finishing.

Machine surface

5 / 5

Can an agent query the system, or must it read files and guess?

  • .mcp.json registers adsa.

At 5. An MCP server or CLI that ships inside the package and answers from the installed version, so answers match the version the project has.

Docs coverage

1 / 5

Does every component a consumer can import have a guide?

  • 3 of 6 importable components have a guide (50%).
  • Undocumented, first few: Badge, Modal, Table.
  • CI runs a documentation check.

To reach 3: Most have one, and nothing stops a new component from shipping without one.

Docs freshness

1 / 5

If a guide drifts from the code, does anything notice?

  • 4 guides, 7 code blocks, 0 with a prop table.
  • No guide is marked as generated, so every table is hand-maintained.
  • 1 imports in the guides name symbols this repo does not export, e.g. ButtonGroup in guidelines/button.md.
  • Nothing compares the guides to the code.

To reach 3: Prop tables or examples are generated, but regenerating is a manual step somebody has to remember.

Tokens

3 / 5

Are colour, spacing, radius and motion documented as named decisions?

  • Token documentation: guidelines/design-tokens.md.
  • Motion documented; spacing documented.
  • 2 raw palette classes in guide examples, e.g. bg-gray-100, text-blue-600.

To reach 5: Semantic tokens documented as tables, raw palette usage forbidden by lint, and motion and spacing covered as well as colour.

Patterns

1 / 5

Is there anything above component level — how a real page is assembled?

  • Components only. Nothing describes how a page is assembled.

To reach 3: A pattern-to-component map: for this task, reach for these parts.

Accessibility documentation

1 / 5

Do the guides say which keys a component answers to and what name it needs?

  • 0 of 4 guides carry a keyboard or accessibility section (0%).
  • No automated accessibility check found.

To reach 3: Some guides mention it, written by hand and unevenly.

Verification

3 / 5

Can an agent check its own work before calling it done?

  • 0 test files, 0 stories.
  • No test, typecheck or lint script.
  • CI: .github/workflows/adsa.yml.
  • The agent-readiness score itself is gated in CI.

To reach 5: Every story rendered and checked for accessibility in CI, with a baseline that can only shrink, and one documented command an agent runs before finishing.

Gap handling

3 / 5

What happens when the system genuinely does not have the thing?

  • A list of known absences exists: GAPS.md.
  • The agent instructions tell the agent to stop and ask instead of inventing.
  • No way for an agent to report a new gap where the next agent will read it.

To reach 5: The list, plus an explicit stop-and-ask rule in the agent instructions, plus a way to report a new gap that lands where the next agent reads.
